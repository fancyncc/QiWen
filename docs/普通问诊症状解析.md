# 普通问诊：结构化症状事实与歧义确认

2026-09-27，依据岐问自有实现编写。实现位于 backend/app/symptoms.py，通过 workflow.inquire 接入既有流程；淡蓝页面和安全预审路径保留。

## 实际采用的方法

逐次提取症状事实，使用局部作用域规则判断否定、双重否定、程度与时间；按患者和时间合并；不能明确解释的表述进入针对性追问。没有增加模型调用或使用否定集合覆盖肯定集合。

事实字段包括 id、symptom、subject、assertion、time_scope、degree_text、trend_text、duration_text、correction、source。source 保存消息 ID、会话、原文、字符位置和采集时间。assertion 有 present、absent、uncertain、unspecified；unspecified 表示只描述变化，不能据此认定症状存在或不存在。

旧 symptoms/denied_symptoms 由当前患者、当前时间范围的有效事实派生，兼容原页面与检索。程度保存原文，不自动换算医学分级。

| 表达 | 结果 |
| --- | --- |
| 头痛没有咳嗽 | 头痛肯定，咳嗽否认；后续否定不倒灌到前一个症状 |
| 不是没有咳嗽 | 常见明确双重否定按肯定记录 |
| 不能排除咳嗽 | 不确定，先问目前是否咳嗽 |
| 咳嗽不明显 | 肯定，程度保留“不明显” |
| 咳嗽没有加重 | 只记录变化；无既有肯定事实时先确认是否有症状 |
| 没有咳嗽、发热和鼻塞 | 否定延续到并列列表 |
| 以前咳嗽，现在没有咳嗽 | 既往肯定和当前否认同时保留，既往不加入当前检索词 |
| 咳嗽，没有咳嗽 | 同时间冲突，不让否认静默覆盖肯定；确认前不进入检索或治疗生成 |

## 跨轮、主体和确认

普通症状事实位于会话安全状态 JSON 的 symptom_facts 中，问诊待确认项位于 clinical[subject].symptom_pending。主体切换分别恢复 pending_context、pending_question、symptom_pending；全局事实仍按主体区分。

当前明确时间或更正表述标记旧记录 superseded_by，保留原始来源；不同时间事实不相互覆盖。同时间肯定/否认冲突、存在性不确定或仅有既往记录，生成一个指定症状的问题。

“有”“没有”等短答案只在一个明确的症状确认问题下绑定，记录来源问题。明确带症状名称的当前回答也可完成确认。“不知道”或“跳过”不消除问题，不进入后续分析。

附件中的主体默认未知，先确认归属；确认后保留附件来源。明确其他人的症状不会进入本人的当前症状集合。症状事实不会自动成为长期画像。

memory_load 每轮恢复业务库成功提交的状态，避免使用取消运行的半成品检查点。最终答复与症状事实通过已有版本检查，在同一业务事务内提交；取消或失败不提交新的事实。无需新表迁移，旧未完成主诉首次读取时转为带 legacy 来源的记录。

部署前业务库及检查点备份保存在 .replica-backup/20260927-before-symptom-upgrade/，不进入 Git。

## 下游使用与可观测性

普通问诊有待确认项时返回 consult，结束本轮，不执行 search、bianzheng、formula。确认完成后再按原路由继续。仅否认当前症状时不会为该否认症状生成治疗内容。

_context 向后续分析传递带时间、程度和变化的事实描述。检索继续只使用当前肯定症状；trace.inquiry 包含 facts 和 pending，历史消息和最终响应均能检查实际结果。
