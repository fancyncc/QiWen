# 证据质量问题修复记录（2026-10-12）

## 修改结果与应用边界

本轮针对“向量索引正常、重排正常，但阴虚知识问题和失眠问诊没有引用”的问题。知识学习与个人问诊使用不同资料入口，保留现有 LangGraph 循环，没有新增 ReAct 层、会话记忆面板或跨会话症状引用。

| 问题 | 已实现的修改 | 主要代码 |
| --- | --- | --- |
| 古籍扩展词第三轮才参与，预算已被耗尽 | 首轮同时召回现代原词/别名与有出处的古籍相关词，批量嵌入，融合后只执行一次重排 | app/terms.py、app/retrieval.py |
| 扩展出处只校验格式 | 加载词表时核对随项目提供的原文内容及内容 ID；扩展仍只是 retrieval_related，不进入患者事实 | app/terms.py |
| 定义问题统一依赖古籍词语提及 | 单概念释义选择已核实的公开概念资料；指定书名和个人问诊保持古籍入口 | app/query_plan.py、app/evidence_sources.py、app/knowledge.py |
| 评分窗口混入大量无关方剂 | 同段落最短完整句段覆盖查询词，并保留同段必要上下文；标题/章节只进入评分文本，不混入原文引文 | app/classics.py |
| 无法解释证据在哪一步被丢掉 | 保存召回各通道名次、是否进入候选池、实际窗口和原文偏移、内容指纹、分数及拒绝原因 | app/retrieval.py、app/classics.py |
| 无法确认 tokenizer 是否截断 | 使用实际 CrossEncoder tokenizer 测量输入 token 数、模型上限与截断状态 | app/local_ranking.py |
| 诊断详情挤占 Agent 上下文 | 模型工具结果只保留证据 ID、标题、章节和摘录；诊断留在检索轨迹。通用测评摘要默认不导出问题正文 | app/context.py、evaluation/deployment.py |
| 门槛缺少独立校准 | 导出待复核片段，绑定资料/窗口/分数；开发与验证分组，检查难负例和重复样本；只生成提案，不自动改门槛 | evaluation/evidence_audit.py、evaluation/calibration.py |

概念资料目前仅收录 [NLM MeSH D016710 的阴虚范围释义](https://meshb.nlm.nih.gov/record/ui?ui=D016710)的中文译述，记录 URL、条目标识、核实摘句及日期。其用途是术语学习，不是个人诊断标准。关系、比较、多概念和治疗问题不会用这个单定义替代所需证据；未覆盖的概念不自动生成入库。

## 原因如何得到验证

第一轮修改后，阴虚问题取得证据，重排最高分约 0.908，但四个失眠/续问结果仍无引用，最高分约 0.661。诊断确认这次没有 tokenizer 截断：74 个实际评分输入均可完整容纳，最大 390 tokens，模型上限 512。

失眠首位候选是《金匮要略》“血痹虚劳病脉证并治”的真实片段。此前送入评分的窗口包含相关句以及后续大段方剂和其他条文，范围为正文偏移 33–389。改为同段的相关完整句段后，范围为 33–49，仍保留原书名、章节与原文指纹。最高分约 0.751，通过原有 0.7 门槛；并未降低门槛或把低分资料补回。

这说明窗口混入无关内容是本批失眠样例的可观测影响因素。该分数不能解释成患者确诊概率；该出处也不等于已证明完整诊疗方案。
