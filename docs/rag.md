# 岐问古籍检索与会话上下文（RAG）

检索对象为公开古籍。问诊事实来自当前会话按对象保存的成功状态，跨会话只读取符合条件的本人画像；其他会话的症状、附件、待答问题和自动摘要不参与检索或模型输入。知识追问使用同会话公开话题状态，并重新检索公开证据。ContextBundle 记录实际 injected/dropped IDs；工具结果保持有效 JSON 和完整证据记录。

本文合并古籍混合检索、术语扩展与会话上下文边界。配置和模型准备统一见 [deployment.md](deployment.md)，数据切片见 [data_pipeline.md](data_pipeline.md)，历史测评结果见 [evaluation_report.md](evaluation_report.md)。

| 检索对象 | 候选来源 | 重排 | 失败行为 |
| --- | --- | --- | --- |
| 古籍片段 | SQLite BM25、可选 Chroma 向量 | 本地 CrossEncoder + MMR | 向量失败退 BM25；重排失败不引用；MMR 失败仅用过门槛结果 |

健康接口返回配置模式；实际检索模式、空结果、降级与来源以消息 trace 为准。不能以接口已接入推断检索质量提升。

## 当前执行顺序

当前患者当前肯定症状 → 首轮同时构造现代原词与有出处的古籍相关词查询 → BM25 多查询＋一次批量向量召回 → 按片段 ID 做 RRF → 一次本地 CrossEncoder → sigmoid 分数 ≥ 0.7 → 候选之间的相似度与 MMR → 最多取用 4 个片段。等价计划复用本次请求缓存，不重复耗费重排预算。

terms.search_plan 构造查询，retrieval.retrieve_candidates 召回和融合，local_ranking 执行本地推理、MMR，classics.retrieve_classics 管理筛选和来源校验，workflow.search 接入原流程。RRF 在 CrossEncoder 之前，后面不再用 RRF 覆盖排序。

每个查询默认两路各召回 30 条，保留各查询的通道名次，bm25_rank/vector_rank 表示该通道最佳名次。同一片段只保留一次，RRF 分数为各查询各通道的 1/(60+名次) 之和除以查询数，避免扩展次数增多导致通道权重失衡。默认 CPU 仅 12 个融合候选进入一次重排（可配置），两路原始分数不直接相加。

## CrossEncoder 的真实打分

默认模型为 [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)。模型联合读取“查询—片段”，每对文本输出一个原始 logit。代码显式设置 Identity 激活，再统一执行一次稳定的 sigmoid，score=1/(1+exp(-logit))。不能对模型已经归一化的分数再次 sigmoid。

仅 score≥0.7 的片段进入下一阶段：包括恰好 0.7，0.699999 不通过。程序校验数量、单标签及有限数值。无合格结果可以为空，不用 RRF、BM25 或查询余弦替代这个门槛，也不强凑 4 条。sigmoid 分数不等于校准后的医学概率；0.7 是用户指定的工程值，后续需要标注检索样本评估召回与误收。

不再使用聊天模型自行生成相关性 JSON。CrossEncoder 独立于聊天模式和聊天接口密钥，可以在聊天 mock 时执行。[Sentence Transformers 接口](https://www.sbert.net/docs/package_reference/cross_encoder/model.html)支持显式激活函数，本项目固定相容的 5.1.2 版本。

重排输入为书名/章节加最多 380 字的原文窗口；选择同一段落中覆盖最多查询词的最短完整句段，并保留同段前后各一句的必要上下文。不为填满预算拼入其他段落的方剂或无关内容。遇到超长无标点句只能截取，记录 complete_sentences=false。引用只用正文真实子串，书名/章节不混入引文。window 记录原文偏移、正文指纹与命中词；token_diagnostic 使用实际 tokenizer 测量 token 数及是否超过模型上限。无字面命中的语义候选采用首窗口并记录该局限，不能声称审查了全文。

## MMR 与候选之间的相似度

查询对每个候选的相关性不能当作两个候选之间的相似度。默认独立本地嵌入模型 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5)编码合格候选正文，再算归一化向量的两两余弦。负余弦按零重复程度处理。此模型可与召回模型不同，但同一次 MMR 必须使用同一嵌入模型和维数。

每次选择：

MMR(d) = λ × CrossEncoder相关性(d) − (1−λ) × max(与已选片段的余弦相似度)

默认 λ=0.7。先选相关性最高的一条；随后逐条权衡与已选集合的最大重复程度。λ 越大越重视相关性，越小越重视多样性。并列时按相关性、RRF 名次、ID 确定稳定结果。MMR 分数可能小于 0.7，不能再以 0.7 过滤它；门槛只作用于 CrossEncoder sigmoid 分数。

完全相同的正文（忽略多余空白）先去重，保留相关性排序靠前的来源。近似内容通过 MMR 抑制，但 MMR 不保证所有取用片段彼此不同。仅处理已通过阈值的集合，不能补回低分片段。

来源在重排后和 MMR 后分别与业务库核对，等待期间被删改的片段剔除。取消、超时向线程发送停止信号，每批之间检查；正在执行的单批张量操作可能结束，但取消后的运行不能提交成功答复。

## 失败与空结果

- 向量召回未配置、空索引或接口失败：召回退为 BM25，后续仍执行本地 CrossEncoder 与 MMR。
- CrossEncoder 缓存/依赖缺失、推理失败、超时或无效输出：不引用，不能以字面命中绕过 0.7。
- 所有分数低于 0.7：无引用；原查询的三阶段检索仍最多重试 3 次。
- MMR 嵌入不可用：记录失败，只按已通过 0.7 的相关性排序取用，不假称完成多样性筛选。
- 合格候选零条/一条：无需两两相似度，MMR 标记 not_needed。
- 管理员显式设 rerank mode=none：兼容旧字面检索，但注明未经过门槛和 MMR。默认不会进入此路径。

## 症状与古籍扩展

backend/resources/symptom_terms.json 保存版本化现代症状、别名及有古籍原文出处的扩展词；启动时验证出处 ID 与引文确实匹配随项目提供的古籍。首轮同时召回原词/别名和古籍相关词，原语义查询保留程度、持续时间、变化；独立的 rerank_query 保留原症状与古籍相关词，不把扩展词当成患者陈述。否认、既往和其他患者事实不加入。

扩展项 relation=retrieval_related，记录 id/book/chapter/quote；ID 是书名加正文的 SHA256。出处只能证明词存在，不能证明医学等价，扩展词不回写患者事实或长期画像。

未收录不适先形成 mapping 确认问题，确认后保留原文。例如“我有头皮发紧三天”不被强制改为古籍症状；“打嗝”等歧义口语也保留原词。过敏、孕哺、用药继续走安全流程。词表和提取仍是有限规则，不宣称理解任意复杂句子。

## 轨迹与验收

“什么是…”一类单概念释义优先选择 concept_evidence.json 中匹配且核实来源的概念资料，仍经过同一 CrossEncoder 门槛；《指定书名》问题与个人问诊仅检索古籍。当前只收录已核实的 NLM MeSH 阴虚范围释义译述，记录公开 URL、条目标识、来源摘句及日期；并非临床诊断标准。比较、关系、治疗问题不以该单定义替代所需证据。未覆盖概念不会自动生成入库。来源链接随知识答复展示。

recall_audit 保存各查询通道的名次及是否进入候选池。rerank.input_windows/ranked 保存实际评分窗口、分数与拒绝原因；诊断可区分召回漏检、候选池挤出、评分未完成、低于门槛、过门槛后未选用。每轮源库及范围指纹用于核对离线标注对应的资料版本。只读状态接口不展示患者问题或候选正文。

Agent 模型只接收引用 ID、书名、章节和实际摘录，诊断详情保留在会话检索轨迹，避免占用模型上下文容量。部署测评驱动对合成任务显式启用详细诊断导出；普通 retrieval_summary 默认不导出问题正文和评分摘录。

trace.classics_retrieval.attempts/final 包含查询计划、实际召回模式、两路名次和 RRF、rerank、mmr。rerank 记录 logit、sigmoid 分数、门槛、是否通过，状态 success/no_candidates/model_unavailable/failed/disabled。MMR 记录候选数、重复数、模型、λ、状态；选中片段记 mmr_score/rank/max_selected_similarity。大向量和完整矩阵不写入消息。

本地推理写入 trace.model_calls，role=cross_encoder、node=search，含耗时和状态，Token 为空，不伪造聊天 Token。filtered_count 是门槛剔除，stale_count 是来源变化，truncated_count 是名额限制。

工程测试覆盖精确 0.7、低分不补位、一次 sigmoid、形状与 NaN、取消/超时、两两相似度、多样性、完全重复、MMR 失败仍遵守门槛以及来源二次校验。合成测试不能代替真实模型质量评估。缓存模型后还应通过服务 API 核对实际 rerank/MMR success。

完整真实聊天＋向量＋CrossEncoder＋MMR 验收入口为 docker compose exec backend python -m scripts.check_live，要求向量成功、重排成功、取用分数达标、MMR 成功或确实不需要。聊天/召回接口未配置时不能通过完整链路验收，也不能用健康接口 rag_mode=hybrid 代替。

## 会话记忆：查询补全

查询由当前消息、当前对象已提交状态保留的 pending_context 和附件前 300 字组成。例如上一轮“我头痛”，本轮“三天，未有其它不适”，查询保留“头痛”，不会只检索“三天”。不能把追问模板中的“是否有某症状”当成用户报告，因此不导入 pending_question 的建议词。

问答流程使用按对象保存的原始主诉和症状事实续接短回答，不再注入未经对象过滤的近期用户消息。取消或失败请求的原文不会通过这一途径进入后续上下文。所有问答均不执行跨会话症状摘要召回；本人咨询可参考用户画像，代问和知识交流不加载本人画像。

## 查询构造与检索预算

查询构造由 `app.query_plan` 与症状词表共用：知识提问用中文分词、领域词和显式书名/章节限定；BM25 可使用完整问题召回，字面准入只使用有效词语，不要求古籍包含整句现代问题。指定的书名或章节未匹配时不引用其他资料代替。问诊与 Agent 查询只使用当前咨询对象的有效症状和描述，模型自行写出的查询不能加入已否认或其他患者的症状。

`QIWEN_RAG_TOTAL_TIMEOUT` 默认 30 秒，可配置为大于零且不超过 300 秒。同一请求的 fixed/multi 检索及重试共用截止时间，向量、重排、MMR、排队只能使用剩余预算。只在无相关资料、查询确有变化且预算足够时改写；相同查询缓存本次有效结果，基础设施故障停止重试。缓存不跨请求或会话，复用前再次检查来源。

下一次检索至少预留上一轮实测耗时的 1.1 倍，且不低于 50 毫秒；只剩几秒时不再启动预计需要十几秒的 CPU 重排。这是保守预算判断，不保证供应商时延稳定。部署报告保留整个检索历史及最高重排分数，不能只记录最后一次改写的结果。

`QIWEN_RAG_RECALL_K` 默认 30，`QIWEN_RAG_CANDIDATES` 可显式配置 4～40。CPU CrossEncoder 默认重排前 12 个候选，其他模式默认 30；这是候选筛选优化，0.7 门槛保持不变。4 线程下 16 候选实测重排需 27.33 秒，无法为默认 30 秒总预算内的向量查询和 MMR 留足时间。开发代理标签下 16 与 30 候选覆盖均为 45/46，12 候选为 44/46；缩减候选有召回代价，需专业复核。资源充足时可显式提高候选数，该比较不代替真实重排和专业证据质量验收。

`QIWEN_LOCAL_MODEL_THREADS` 默认取可见 CPU 数与 4 的较小值，可显式配置 1～16。`/api/health` 只表示进程可用；`/api/readiness` 另查当前语料 ID 的实际向量覆盖、配置是否齐全及最近五分钟的检索状态，不调用供应商、不下载模型、不返回患者输入。向量为空或最近检索失败会标记 degraded，未探测过不会宣称 ready。部署报告保留负载前后的就绪状态，发布验收要求检索就绪。

hybrid 与 CrossEncoder 模式下，启动时默认用最多 30 秒预热本地已缓存的重排及 MMR 权重，减少首轮查询加载开销；不会自动下载模型。缺少权重或预热失败会在就绪检查中标记 degraded，进程仍可启动以供排查。显式设置 `QIWEN_RAG_WARMUP=false` 可关闭预热；随后仍需用实际检索验证就绪。

向量索引按 ID 断点续建。若供应商处理长文本批次超时，可显式执行 `python -m scripts.index_vectors --batch-size 8`，减小单次输入；默认 32，允许 1～128。已有片段不会重复嵌入，也不需要增大聊天检索超时。

`retrieval_trace.outcome` 区分成功、无匹配、超时、模型不可用、依赖异常、空语料和索引状态；`timings` 保留 BM25、向量、排队、模型加载、重排及 MMR 的阶段耗时。本地推理最多允许四个运行或排队任务；等待锁的过期任务不加载模型。取消会停止后续批次，当前张量操作可能继续完成，实际线程结束前不释放其容量。MMR 失败仍可使用已经通过 0.7 门槛的资料，不能借此绕过重排准入。

## 会话内记忆与跨会话画像

`thread_safety_state` 保存当前会话的症状、风险事实和按对象区分的待答问题。`consultation_episodes` 保存会话内病程摘要及版本，保留来源、持续时间、变化和明确否认。新会话从空问诊状态开始，不继承另一会话的附件或知识话题。

跨会话只使用手填 `profiles` 与用户明确确认的 `patient_safety_facts`。过敏史等长期资料可作背景，用药和孕哺等时效资料在新会话按需复核。普通症状和模型推断不自动成为画像。本人、亲属及未知对象仍分别处理。

旧 `profile_memories`、归属、向量、词索引和控制表保留用于兼容删除，退出所有模型输入；不生成新摘要，不回填索引，不执行嵌入、重排或运行级记忆缓存。旧检查点的 memory_context/memory_records 通道不导入新工作流；历史摘要来源的风险事实被排除。原有记忆检索环境变量不再生效。

上下文必需信息包括当前输入、同会话有效事实、适用画像、待回答问题及必要附件摘录。公开证据按整条记录裁剪；每次模型请求再统一检查系统提示、Schema、工具协议与输出预留。资料超过容量时明确要求缩小输入，不通过字符串截尾丢弃风险信息。
