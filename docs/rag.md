# 岐问检索与记忆（RAG）

本文合并古籍混合检索、术语扩展与会话记忆读取。配置和模型准备统一见 [deployment.md](deployment.md)，数据切片见 [data_pipeline.md](data_pipeline.md)，历史测评结果见 [evaluation_report.md](evaluation_report.md)。

| 检索对象 | 候选来源 | 重排 | 失败行为 |
| --- | --- | --- | --- |
| 古籍片段 | SQLite BM25、可选 Chroma 向量 | 本地 CrossEncoder + MMR | 向量失败退 BM25；重排失败不引用；MMR 失败仅用过门槛结果 |
| 本人其他会话摘要 | SQLite BM25、可选缓存嵌入余弦 | 独立 `memory_rerank` 聊天模型角色 | 向量失败退 BM25；重排失败保留融合排序并记录 |

健康接口返回配置模式；实际检索模式、空结果、降级与来源以消息 trace 为准。两类重排不能互相替代，也不能以接口已接入推断质量提升。

## 当前执行顺序

当前患者当前肯定症状 → 保留现代原意的查询 → BM25＋向量分别召回 → 按片段 ID 做 RRF → 本地 CrossEncoder → sigmoid 分数 ≥ 0.7 → 候选之间的相似度与 MMR → 最多取用 4 个片段。

terms.search_plan 构造查询，retrieval.retrieve_candidates 召回和融合，local_ranking 执行本地推理、MMR，classics.retrieve_classics 管理筛选和来源校验，workflow.search 接入原流程。RRF 在 CrossEncoder 之前，后面不再用 RRF 覆盖排序。

两路默认各召回 30 条，保留 bm25_rank/score、vector_rank/similarity。同一片段只保留一次，RRF 分数为命中通道的 1/(60+名次) 之和；最多 30 条融合候选进入重排，两路原始分数不直接相加。

## CrossEncoder 的真实打分

默认模型为 [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)。模型联合读取“查询—片段”，每对文本输出一个原始 logit。代码显式设置 Identity 激活，再统一执行一次稳定的 sigmoid，score=1/(1+exp(-logit))。不能对模型已经归一化的分数再次 sigmoid。

仅 score≥0.7 的片段进入下一阶段：包括恰好 0.7，0.699999 不通过。程序校验数量、单标签及有限数值。无合格结果可以为空，不用 RRF、BM25 或查询余弦替代这个门槛，也不强凑 4 条。sigmoid 分数不等于校准后的医学概率；0.7 是用户指定的工程值，后续需要标注检索样本评估召回与误收。

不再使用聊天模型自行生成相关性 JSON。CrossEncoder 独立于聊天模式和聊天接口密钥，可以在聊天 mock 时执行。[Sentence Transformers 接口](https://www.sbert.net/docs/package_reference/cross_encoder/model.html)支持显式激活函数，本项目固定相容的 5.1.2 版本。

输入是原文中最多 500 字的窗口，优先覆盖本次查询词，始终是数据库正文的真实子串。tokenizer 仍按最大长度截断，不能声称审查了无限长全文。引用使用实际提供的窗口，保留 ID、书名和章节；既有用药内容显示限制继续生效。没有生成新患者症状或自造出处。

## MMR 与候选之间的相似度

查询对每个候选的相关性不能当作两个候选之间的相似度。默认独立本地嵌入模型 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5)编码合格候选正文，再算归一化向量的两两余弦。负余弦按零重复程度处理。此模型可与召回模型不同，但同一次 MMR 必须使用同一嵌入模型和维数。

每次选择：

MMR(d) = λ × CrossEncoder相关性(d) − (1−λ) × max(与已选片段的余弦相似度)

默认 λ=0.7。先选相关性最高的一条；随后逐条权衡与已选集合的最大重复程度。λ 越大越重视相关性，越小越重视多样性。并列时按相关性、RRF 名次、ID 确定稳定结果。MMR 分数可能小于 0.7，不能再以 0.7 过滤它；门槛只作用于 CrossEncoder sigmoid 分数。

完全相同的正文（忽略多余空白）先去重，保留相关性排序靠前的来源。近似内容通过 MMR 抑制，但 MMR 不保证所有取用片段彼此不同。仅处理已通过阈值的集合，不能补回低分片段。

来源在重排后和 MMR 后分别与业务库核对，等待期间被删改的片段剔除。取消、超时向线程发送停止信号，每批之间检查；正在执行的单批张量操作可能结束，但取消后的运行不能提交成功答复。

## 失败与空结果

- 向量召回未配置、空索引或接口失败：召回退为 BM25，后续仍执行本地 CrossEncoder 与 MMR。
- CrossEncoder 缓存/依赖缺失、推理失败、超时或无效输出：不引用，不能以字面命中绕过 0.7。
- 所有分数低于 0.7：无引用；原查询的三阶段检索仍最多重试 3 次。
- MMR 嵌入不可用：记录失败，只按已通过 0.7 的相关性排序取用，不假称完成多样性筛选。
- 合格候选零条/一条：无需两两相似度，MMR 标记 not_needed。
- 管理员显式设 rerank mode=none：兼容旧字面检索，但注明未经过门槛和 MMR。默认不会进入此路径。

## 症状与古籍扩展

backend/resources/symptom_terms.json 保存版本化现代症状、别名及有古籍原文出处的扩展词；数量随词表维护变化，不作为固定协议。先用原词，第二次加别名，第三次加有出处的古籍词，每次保留现代原意。向量/CrossEncoder 查询含当前患者当前肯定症状和原文中的程度、持续时间、变化，否认、既往和其他患者事实不加入。

扩展项 relation=retrieval_related，记录 id/book/chapter/quote；ID 是书名加正文的 SHA256。出处只能证明词存在，不能证明医学等价，扩展词不回写患者事实或长期画像。

未收录不适先形成 mapping 确认问题，确认后保留原文。例如“我有头皮发紧三天”不被强制改为古籍症状；“打嗝”等歧义口语也保留原词。过敏、孕哺、用药继续走安全流程。词表和提取仍是有限规则，不宣称理解任意复杂句子。

## 轨迹与验收

trace.classics_retrieval.attempts/final 包含查询计划、实际召回模式、两路名次和 RRF、rerank、mmr。rerank 记录 logit、sigmoid 分数、门槛、是否通过，状态 success/no_candidates/model_unavailable/failed/disabled。MMR 记录候选数、重复数、模型、λ、状态；选中片段记 mmr_score/rank/max_selected_similarity。大向量和完整矩阵不写入消息。

本地推理写入 trace.model_calls，role=cross_encoder、node=search，含耗时和状态，Token 为空，不伪造聊天 Token。filtered_count 是门槛剔除，stale_count 是来源变化，truncated_count 是名额限制。

工程测试覆盖精确 0.7、低分不补位、一次 sigmoid、形状与 NaN、取消/超时、两两相似度、多样性、完全重复、MMR 失败仍遵守门槛以及来源二次校验。合成测试不能代替真实模型质量评估。缓存模型后还应通过服务 API 核对实际 rerank/MMR success。

完整真实聊天＋向量＋CrossEncoder＋MMR 验收入口为 docker compose exec backend python -m scripts.check_live，要求向量成功、重排成功、取用分数达标、MMR 成功或确实不需要。聊天/召回接口未配置时不能通过完整链路验收，也不能用健康接口 rag_mode=hybrid 代替。

## 会话记忆：查询补全

查询由当前消息、检查点保留的 pending_context 和附件前 300 字组成。例如上一轮“我头痛”，本轮“三天，未有其它不适”，查询保留“头痛”，不会只检索“三天”。不能把追问模板中的“是否有某症状”当成用户报告，因此不导入 pending_question 的建议词。

没有待追问描述时，纯时长或简单肯定、否定的短回答，可使用最近用户原文补充；明确的新问题不自动拼接上一话题。当前消息从近期消息中按完整原文剔除，再截断历史原文，避免长消息重复。

## 会话记忆：召回与独立模型重排

1. SQLite 查询本人其他会话最近 20 份摘要，校验摘要和会话均属于本人。当前会话通过检查点和近期原文续接，不再重复加入自己的摘要。
2. BM25 排关键词结果。检索分词使用中文二字组合、英文词，过滤通用描述与时长，包含少量已知同义表达。原始摘要不改写。
3. BM25 分支要求至少存在有效词重合，且覆盖查询词集合至少四分之一。六组有标注的离线样例验证头痛、睡眠同义表达，以及腰痛、纯时长、泛化不适的空结果。此门槛是当前小样例的工程基线，不代表已完成真实语料质量评测。
4. 配置嵌入接口和校准后的余弦门槛时，计算语义向量结果；低于门槛的候选不入融合。
5. 每路最多 10 条候选，RRF 按 `1/(60+排名)` 融合，保留最多 10 条供重排。RRF 分数只是排名信号，不能当作相关性概率。
6. 独立 `memory_rerank` 模型角色根据完整问题、来源、摘要更新时间与原文选择有用途的候选并排序，最终最多取 3 条。模型可以返回空数组，不凑足数量。当前实现为大模型列表重排，不是 CrossEncoder，也没有接厂商专用 /rerank 接口。

目前每人最多 20 条候选，向量分支直接计算余弦相似度，使用 SQLite 缓存摘要向量，无须另加向量数据库。缓存绑定用户、来源会话、摘要内容哈希、接口基址与嵌入模型。摘要改变时重算，删除摘要或会话时缓存随外键级联删除；最终结果再次核对业务库，已删除记录不能通过旧索引恢复。

## 会话记忆：来源和上下文

每条被使用的摘要保留来源会话 id、摘要更新时间和用户自述原文，包括否定和时间用语。摘要更新时间不是症状发生时间，不能用更新时间代替原文中的“上个月”等表达。

上下文先放当前会话近期用户原文，再放带来源的历史摘要，总预算 1200 字。单条摘要正文最多 300 字；超预算时整段舍弃，不能把来源标记截掉。向模型传入上下文时不再额外从 900 字截断。提示明确历史自述不是本轮已确认症状，不能覆盖当前说明；这不是模型绝不会误读的保证。

最终消息的 `trace.memory_retrieval` 记录请求模式、实际模式、退化原因和选中摘要的来源/更新时间/命中通道，不记录嵌入密钥。选中的摘要可能进一步受上下文预算限制。

## 会话记忆：重排边界

重排请求只发送本人已通过检索门槛的候选。模型返回严格 JSON `ordered_ids`，数组只能包含现有候选 id，不得重复，不得添加其他字段。未返回的候选视为拒绝，空数组是有效结果。摘要由程序从原候选读取，模型不提供改写正文。

调用前、调用后均检查摘要仍存在、归属正确、原文与更新时间未改变。未知编号、重复编号、无效结构、超时或接口失败时保留现有融合排序并记录失败；任务取消则继续向上抛出取消，不返回退化答复。候选全部被删除或改动时返回空结果。

提示要求保留否定与时间含义，历史记录不能自动变成本轮症状；模型可能误判，仍需要真实样例验收。`model_calls` 中记录该角色的模型、耗时、重试和可用的 Token 用量，失败详情不会记录密钥或完整病历。

## 记忆配置缺失与质量验证

记忆模式独立于古籍 `QIWEN_RAG_MODE`。嵌入配置或校准门槛缺失、非法响应或调用失败时退为 BM25，并记录原因；没有默认伪向量。记忆嵌入使用 SQLite 缓存，不依赖古籍 Chroma 的安装开关。

`QIWEN_MEMORY_RERANK_MODE=llm` 默认请求模型重排，`none` 明确禁用。缺少兼容接口、凭据或模型名时记录 `skipped_unconfigured`；无候选时为 `no_candidates`，不发模型请求。`rerank.status` 的 success、no_candidates、disabled、skipped_unconfigured、fallback 分别表示实际执行结果，后四项不能当作成功重排。

门槛应针对真实嵌入模型用相关/无关、不同措辞、否定、过时资料及短回答等标注案例校准，划分调参与独立验收样例。模型变化后重新评估；同一独立集比较重排前后误选、漏选、延迟与成本。合成向量、模拟 HTTP 和 Mock 测试只验证工程契约，不能代替真实模型质量评估。
