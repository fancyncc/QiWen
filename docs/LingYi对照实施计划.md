## 实施顺序与完成条件

1. **基线**：固定参考版本、执行测试和 Docker/页面检查，建立差距清单（本文件）。
2. **真实服务**：本机配置兼容模型与嵌入接口，导入古籍向量；固定和多专家模式各完成一轮问答，并确认引用来自实际片段。缺少接口配置时继续离线工作，但此项保持未验收。
3. **会诊正确性**：覆盖并行结果、重试替换、上一轮药材加药检查、终止与刷新一致性。禁止未通过审查的候选药材出现在最终展示或历史中。
4. **知识与工具**：只导入来源、授权和提取质量可核实的数据。重排、MCP、WebSocket、网络搜索逐个接入并单独验收。
5. **评测与运维**：建立可重复的离线与真实模型评测；完成备份恢复、故障日志和数据保留的部署演练。

每次修改前端、后端或运行配置后，交付前执行 `docker compose up --build -d`，检查 `docker compose ps` 中前后端健康状态，并确认 `/api/health` 和 `/chat` 可访问。

## 本轮实施记录

- 增加可续建的 Chroma 索引和真实模型/嵌入/向量检索检查入口；使用 Chroma 实库和合成向量验证了建索引、重试及混合检索。
- 增加独立的合成问诊评测。Mock 模式 7/7 项通过；真实模式待 `.env` 配置后运行。
- 增加四个本地 MCP 只读公共知识工具，并通过 stdio 客户端握手与配伍查询；患者画像不通过该服务暴露。
- 增加 SQLite 在线快照、上传文件归档和哈希校验恢复；从 Docker 数据卷导出的快照恢复演练保留了 1 个用户和 1537 个古籍片段。
- 后端 16 项测试通过；前端生产构建通过。Docker 重建后前后端均 healthy，`/api/health` 和 `/chat` 均返回 200。
- 真实模型、真实嵌入、知识扩充和人工医学审阅仍未验收。MCP、WebSocket、网络搜索、重排和参考仓库的更大外部数据集分属不同能力；目前先保留 SSE 主链路，待真实环境评测后决定扩展。

## 后续三项工程实施

- 统一异步模型接口：11 类角色覆盖与默认回退、独立超时、有限重试、结构校验、Token 与节点用量持久化。当前四种角色实际接入模型，其余角色接口预留到对应能力升级。
