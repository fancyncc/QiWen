# 检索与测评整改记录

此页保留上一轮的检索超时与测评契约整改记录。2026-10-12 的证据入口、首轮扩展、评分窗口修复及最新验证结果见 [证据质量问题修复记录](evidence_quality_fix_report.md)。

本轮依据正常辨证超时、自然语言查询准入失效、空引用被误判通过以及部署样本不足的结果整改。应用仍以中医问诊、古籍知识问答与同会话续问为背景，保留 LangGraph 循环与患者边界，不增加记忆面板。

## 已落实

1. 应用与评测共用查询构造。知识问句提取有意义的词语、领域概念及用户明确提及的书名章节，字面准入不要求古籍包含完整现代问句。未知标识不能用“是什么”等模板词召回资料。专业标签不参与构造查询。
2. 问诊与 Agent 检索只使用当前对象的有效事实，不引入已否认或他人的症状。跨会话仍只参考明确确认的本人画像，不恢复其它会话症状。
3. fixed/multi 和查询改写共用默认 30 秒的总检索预算。相同计划不重复执行，依赖故障停止改写；超时、依赖故障、索引缺失和正常无匹配分别记录。阶段耗时与候选元数据在超时后仍保留。
4. CPU 重排默认候选 12、线程数为可见 CPU 数与 4 的较小值，仍保留 0.7 相关性门槛。实测 4 线程、16 候选的重排本身需 27.33 秒，无法给默认 30 秒总预算内的向量与 MMR 留足余量，故进一步缩减。候选覆盖代理比较中 16 与 30 均为 45/46，12 为 44/46；有召回代价，需专业复核，资源充足可显式提高候选数。取消后停止后续批次，实际线程结束前不释放容量。MMR 失败仅能保留已经通过重排的证据。
5. 服务启动可预热本地缓存权重，不自动下载。`/api/readiness` 检查真实语料 ID 的向量覆盖、模型预热和最近检索结果；进程健康不再代表检索就绪。该端点不包含患者输入或供应商配置值。
6. 测评分别判断请求契约、最终证据和实际并发覆盖。加入问候、知识、辨证、无答案与两轮续问场景，要求实际聊天流重叠及足量样本。空证据若由超时或依赖故障导致，不算正确拒答。
7. 发布验收要求专业正反例、预先声明的最终证据相关率与召回率、真实模型及独立评审、人工审核、同版本完整部署负载。Mock 契约通过不能代替发布验收。

尚未解决的是最终证据效果：必须为上述正例补齐专业片段标注，检查正确原文是否被召回、是否出现在重排窗口内，并验证现代问诊描述与古籍表达的适配。候选确实相关但被过滤时，再用独立标注验证模型与准入校准；不凭这三个分数直接降低 0.7。供应商单次查询仍有时延波动，CPU 正例也接近总预算，不能把本次串行零超时推广为并发容量达标。

[明确出处的对照诊断](../backend/evaluation/reports/current/deployment-component-20261011T142923941293Z.json)：问题“《伤寒论》太阳病的提纲是什么？”在 fixed/multi 均正常完成，各返回 2 条证据，最高重排分数 0.7803，MMR 本地推理成功，检索耗时分别 23.93 秒、21.93 秒。这验证了向量、重排、0.7 准入、MMR 和证据输出能完整工作；由此推断泛化问诊与现代概念的查询/语料适配值得优先排查，而不是统一取消重排或降低门槛。此对照不替代五类失败报告，也没有验证临床准确性或真实应用模型质量。
