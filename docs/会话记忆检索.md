# 会话记忆读取与混合检索

更新日期：2026-09-26。实现位于 `backend/app/memory.py`，由 `workflow.memory_load` 调用。仅调整记忆读取，问诊、古籍检索、候选审查的流程保持现有行为。

## 检索问题怎样补全

查询由当前消息、检查点保留的 pending_context 和附件前 300 字组成。例如上一轮“我头痛”，本轮“三天，未有其它不适”，查询保留“头痛”，不会只检索“三天”。不能把追问模板中的“是否有某症状”当成用户报告，因此不导入 pending_question 的建议词。

没有待追问描述时，纯时长或简单肯定、否定的短回答，可使用最近用户原文补充；明确的新问题不自动拼接上一话题。当前消息从近期消息中按完整原文剔除，再截断历史原文，避免长消息重复。

## BM25 + 向量 + RRF + 模型重排

1. SQLite 查询本人其他会话最近 20 份摘要，校验摘要和会话均属于本人。当前会话通过检查点和近期原文续接，不再重复加入自己的摘要。
2. BM25 排关键词结果。检索分词使用中文二字组合、英文词，过滤通用描述与时长，包含少量已知同义表达。原始摘要不改写。
3. BM25 分支要求至少存在有效词重合，且覆盖查询词集合至少四分之一。六组有标注的离线样例验证头痛、睡眠同义表达，以及腰痛、纯时长、泛化不适的空结果。此门槛是当前小样例的工程基线，不代表已完成真实语料质量评测。
4. 配置嵌入接口和校准后的余弦门槛时，计算语义向量结果；低于门槛的候选不入融合。
5. 每路最多 10 条候选，RRF 按 `1/(60+排名)` 融合，保留最多 10 条供重排。RRF 分数只是排名信号，不能当作相关性概率。
6. 独立 `memory_rerank` 模型角色根据完整问题、来源、摘要更新时间与原文选择有用途的候选并排序，最终最多取 3 条。模型可以返回空数组，不凑足数量。当前实现为大模型列表重排，不是 CrossEncoder，也没有接厂商专用 /rerank 接口。

目前每人最多 20 条候选，向量分支直接计算余弦相似度，使用 SQLite 缓存摘要向量，无须另加向量数据库。缓存绑定用户、来源会话、摘要内容哈希、接口基址与嵌入模型。摘要改变时重算，删除摘要或会话时缓存随外键级联删除；最终结果再次核对业务库，已删除记录不能通过旧索引恢复。

## 来源和上下文

每条被使用的摘要保留来源会话 id、摘要更新时间和用户自述原文，包括否定和时间用语。摘要更新时间不是症状发生时间，不能用更新时间代替原文中的“上个月”等表达。

上下文先放当前会话近期用户原文，再放带来源的历史摘要，总预算 1200 字。单条摘要正文最多 300 字；超预算时整段舍弃，不能把来源标记截掉。向模型传入上下文时不再额外从 900 字截断。提示明确历史自述不是本轮已确认症状，不能覆盖当前说明；这不是模型绝不会误读的保证。

最终消息的 `trace.memory_retrieval` 记录请求模式、实际模式、退化原因和选中摘要的来源/更新时间/命中通道，不记录嵌入密钥。选中的摘要可能进一步受上下文预算限制。

## 重排边界

重排请求只发送本人已通过检索门槛的候选。模型返回严格 JSON `ordered_ids`，数组只能包含现有候选 id，不得重复，不得添加其他字段。未返回的候选视为拒绝，空数组是有效结果。摘要由程序从原候选读取，模型不提供改写正文。

调用前、调用后均检查摘要仍存在、归属正确、原文与更新时间未改变。未知编号、重复编号、无效结构、超时或接口失败时保留现有融合排序并记录失败；任务取消则继续向上抛出取消，不返回退化答复。候选全部被删除或改动时返回空结果。

提示要求保留否定与时间含义，历史记录不能自动变成本轮症状；模型可能误判，仍需要真实样例验收。`model_calls` 中记录该角色的模型、耗时、重试和可用的 Token 用量，失败详情不会记录密钥或完整病历。

## 配置与当前限制

```dotenv
QIWEN_MEMORY_MODE=hybrid
QIWEN_MODEL_BASE_URL=<兼容接口的 v1 基址>
QIWEN_MODEL_API_KEY=<服务端密钥>
QIWEN_EMBEDDING_MODEL=<嵌入模型名称>
QIWEN_MEMORY_MIN_SIMILARITY=<用该模型的标注样例确定的余弦门槛>
QIWEN_MEMORY_RERANK_MODE=llm
QIWEN_MODEL_MEMORY_RERANK=<重排模型名称，留空沿用 QIWEN_MODEL_NAME>
QIWEN_MODEL_MEMORY_RERANK_TIMEOUT=15
QIWEN_MODEL_MEMORY_RERANK_RETRIES=0
```

`QIWEN_MEMORY_MODE=bm25` 可显式只运行关键词分支。记忆模式独立于古籍的 QIWEN_RAG_MODE；嵌入地址与密钥复用已有兼容接口配置，聊天模型仍可保持 Mock。

`QIWEN_MEMORY_RERANK_MODE=llm` 默认请求模型重排；`none` 明确禁用。重排复用兼容聊天接口的基址与密钥，可独立于 Mock 问答调用真实模型，不会连带启用辨证、方剂等其他模型角色。配置角色独立超时与重试以控制额外延迟。缺少接口、密钥或模型名时跳过并记录 `skipped_unconfigured`。没有候选时记录 `no_candidates`，不发模型请求。

嵌入配置缺失、门槛空值、非法返回或请求失败时，只运行 BM25，并记录原因。没有默认伪向量，也不把 BM25 运行报告为混合运行。向量索引不需要 QIWEN_INSTALL_KNOWLEDGE；该配置仍只针对古籍 Chroma 检索。

门槛必须针对实际嵌入模型测量：准备相关/无关、不同措辞、否定、过时资料及短回答等有标注案例；划分调参与独立验收样例，比较误选与漏选，再配置门槛。模型或嵌入接口变化后重新评估。同一组独立案例还应比较重排前后的误选、漏选、延迟与调用成本，不能把接入重排等同于质量已提升。

当前部署没有嵌入和重排模型接口配置，实际运行 BM25，重排状态为未配置时跳过。自动测试使用合成向量、模拟重排输出与模拟 HTTP 响应，验证排序、全部拒绝、隔离、并发删除、取消、超时和退化机制，不代表真实模型质量已验收。

## 验证

在项目根目录运行 `.venv\Scripts\python.exe -m pytest backend/tests/test_memory.py -q`，或在测试容器挂载 backend 后运行同一测试文件。每次后端或配置修改后仍需 `docker compose up --build -d` 并检查服务健康。

重排加入后，记忆与模型适配测试 47 项通过，完整后端 92 项通过、5 项可选 MCP/ChromaDB 测试跳过。已执行 `docker compose up --build -d`，前后端均 healthy，健康接口 status=ok，聊天页 HTTP 200。实际经前端代理用临时账号检查候选来源与时间、no_candidates 和 skipped_unconfigured 状态，测试账号与会话已清理。真实嵌入与重排模型仍未配置和验收；模拟测试不代表真实质量评测。
